# 真实 SSH 验收步骤

请只使用专用临时目录，不使用业务项目。下面的检测不消耗 Claude 推理额度；发送会话消息会使用目标用户的 Claude 额度。

## 1. 准备 SSH

用运行 DSH 的同一系统用户执行：

```sh
ssh -T -o BatchMode=yes -o StrictHostKeyChecking=yes my-box 'id -un; command -v claude; claude --version'
```

首次主机指纹由人工核实，不能使用 StrictHostKeyChecking=no。确保远端 `claude auth status --json` 的 loggedIn 为 true，不要复制或记录令牌。

## 2. 只创建临时测试目录

```sh
ssh my-box 'mktemp -d /tmp/dsh-claude-ssh-accept.XXXXXX'
```

记下返回的绝对路径，在该路径下建立名字含中文、空格、单引号的子目录。macOS 可能规范化为 `/private/tmp/...`，工作区会保存 `pwd -P` 的真实路径。

## 3. 界面和目录

1. 添加主机，测试连接与 Claude。核对实际用户、路径、版本、登录状态。
2. 浏览上述空子目录，看到“空目录”，保存工作区。再建立一个子目录，重新浏览应显示它。
3. 输入一个不存在的目录保存，应报 REMOTE_DIRECTORY，不能建立工作区。
4. 创建会话，确认输入框上方完整显示主机、用户、远端目录。
5. 刷新浏览器、重启隔离 DSH 后再次打开会话，绑定与 Claude ID 应一致。
6. 在本地会话选择该主机模型，应显示未绑定并阻止发送；绕过前端直接调用后端也应拒绝。
7. 添加第二主机标识（可以指向同一测试服务器）及不同目录，选择不匹配的模型，应阻止执行。

## 4. 推理与确认（会消耗额度）

先说明拟执行的动作：仅在临时目录让 Claude 执行 pwd、读取/创建测试文件，并回答一个短问题；不要让它访问业务目录。

1. 发送“执行 pwd，读取当前测试目录中的测试文件并汇报结果”。核对流式文字、远端工具事件和实际路径。
2. 发送需要单次确认的临时文件操作。确认界面应显示远端身份与准确命令；分别测试同意、拒绝。
3. 要求 Claude 使用 AskUserQuestion 提问，确认 DSH 的选项和自定义回答回到远端。
4. 再发一条新问题，确认 CLI 使用同一 Claude session ID 续接，旧消息不再发送。
5. 让它执行一个有界等待，点击停止，确认显示取消；检查远端进程，再明确恢复。
6. 运行中关闭 SSH 连接/测试网络，确认显示中断而不是成功，没有自动重复任务。检查远端后手动恢复，发送新的核对指令。

远端已有允许规则可能令某些读写不弹出确认，不应据此声称确认桥已实测。选择需要确认的动作，或用测试用户的专用 Claude 配置；不要修改现有业务配置去制造弹窗。

## 5. 分类错误和本地隔离

分别使用不存在的 Claude 绝对路径、未登录的专用测试账号、错误端口、错误密钥、未知主机指纹验证提示。不要注销现有账号或篡改生产 known_hosts。

同时打开普通本地 DSH 会话。其文件、命令、模型和目录应仍遵循 DSH 自身配置；远端工具事件不能在本机执行。

## 6. 清理

结束所有测试会话后，仅删除之前记录的 `/tmp/dsh-claude-ssh-accept.*` 专用目录。不要用宽泛通配符清理未知目录。Claude CLI 自身的会话记录由 CLI 管理，插件不会删除。

关闭临时浏览器与隔离 DSH 服务，检查临时 agent-browser profile/守护进程已退出；保留用户正常 Chrome。独立 profile 可使用 DSH_HOME 指向 /tmp，避免影响现有会话和设置。
